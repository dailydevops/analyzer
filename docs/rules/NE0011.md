# NE0011: Avoid `#region` directives

| Property   | Value              |
|------------|--------------------|
| Rule ID    | NE0011             |
| Category   | Style              |
| Severity   | Warning / Suggestion |
| Code fix   | Yes                |

## Cause

A `#region`/`#endregion` directive pair is present in the source file.

## Rule description

`#region` directives encourage hiding code behind a collapsible label instead of decomposing it into
smaller, well-named members or types. A single descriptor reports every occurrence, but the *effective*
severity depends on where the `#region` sits:

- **Warning** when the `#region` is nested inside the executable body of a method, constructor, accessor
  (`get`/`set`/`init`/`add`/`remove`), operator, or local function. Hiding statements inside a member body
  behind a region is the strongest signal that the member has grown too large and should be split up.
- **Suggestion** everywhere else — wrapping a whole type, a group of members, using directives, or any
  other type-, namespace-, or file-level content. This is still discouraged, but less severe than hiding
  executable logic.

Only a `#region` that has a matching `#endregion` is analyzed. Generated code is skipped.

## How to fix violations

Remove the `#region` and `#endregion` directives, keeping the content between them intact. If the region
was used to group related members, prefer extracting them into a well-named nested type, partial class, or
separate file instead.

```csharp
// Before
public sealed class Sample
{
    #region Fields

    private int _value;

    #endregion
}

// After
public sealed class Sample
{
    private int _value;
}
```

The code fix performs this rewrite for a single occurrence, and via Fix All for every occurrence in the
selected scope.

## Suppress a warning

```csharp
#pragma warning disable NE0011
#pragma warning restore NE0011
```
