# NE0005: Use the 'is not null' pattern instead of '!= null'

| Property   | Value   |
|------------|---------|
| Rule ID    | NE0005  |
| Category   | Usage   |
| Severity   | Warning |
| Code fix   | Yes     |

## Cause

A value is compared against `null` with the inequality operator (`x != null` or `null != x`) where a
pattern-based null check (`x is not null`) would express the same intent unambiguously.

## Rule description

A null comparison written with `!=` can be redefined by a user-defined `operator !=`, so the reader cannot be
sure it performs a plain null check. The `is not null` pattern always performs a null check and cannot be
overridden, so it states the intent directly.

- Only the inequality operator against the `null` literal is considered; either operand order is flagged.
- The comparison is reported only when a pattern form is legal and equivalent:
  - The non-null operand must be **patternable** — a non-pointer reference type, a `Nullable<T>`, or an
    unconstrained type parameter. Pointer operands and non-nullable value types are never flagged.
  - Comparisons that resolve to a **user-defined `operator !=`** are left alone, because the pattern would
    change the semantics.
  - Comparisons inside a **LINQ expression tree** (`Expression<T>`) are left alone, because the `is` pattern is
    not allowed there.
- Generated code is skipped.

## How to fix violations

Replace the comparison with the pattern. A code fix is provided, and it emits the strongest form the project's
`LangVersion` supports:

- **C# 9.0 and later** — `x is not null`.
- **C# 7.0 and 8.0** — `!(x is null)`.
- **Below C# 7.0** — the diagnostic is reported but no fix is offered, because no legal pattern form exists.

## Suppress a warning

```csharp
#pragma warning disable NE0005
#pragma warning restore NE0005
```
