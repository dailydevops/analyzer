# NE0006: Use the 'is not null' pattern instead of 'is object'

| Property   | Value   |
|------------|---------|
| Rule ID    | NE0006  |
| Category   | Usage   |
| Severity   | Warning |
| Code fix   | Yes     |

## Cause

A value is tested with `x is object` as a non-null check, where the `is not null` pattern would express the
same intent without being misread as a type test.

## Rule description

`x is object` is a type check that happens to double as a null check — it is true exactly when `x` is not
`null`. Because it reads as "is this an object", the null-check intent is easily missed. The `is not null`
pattern states the null check directly.

- Only the bare `is object` form is considered. A declaration pattern such as `x is object o` binds a variable
  and is left alone.
- The checked value must be **patternable** — a non-pointer reference type, a `Nullable<T>`, or an
  unconstrained type parameter. A non-nullable value type is skipped, because there `is object` is always true
  (it is not a null check at all).
- Expressions inside a **LINQ expression tree** (`Expression<T>`) are left alone, because the `is` pattern is
  not allowed there.
- Generated code is skipped.

The diagnostic is reported regardless of the project's C# language version; the code fix is offered only when
the language version can compile the pattern (see below).

## How to fix violations

Replace the type check with the pattern:

```csharp
// Before
if (value is object) { }

// After
if (value is not null) { }
```

The code fix performs this rewrite and preserves the surrounding trivia. Because the `is not null` pattern
requires **C# 9.0**, the fix is registered only when the project's effective `LangVersion` is 9.0 or later; on
an older version the diagnostic still reports but no fix is offered.

## Suppress a warning

```csharp
#pragma warning disable NE0006
#pragma warning restore NE0006
```
