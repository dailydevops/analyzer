# NE0013: Use a numeric literal suffix instead of casting the literal

| Property   | Value   |
|------------|---------|
| Rule ID    | NE0013  |
| Category   | Style   |
| Severity   | Info    |
| Code fix   | Yes     |

## Cause

A plain integer literal is immediately cast to `long`, `ulong`, `uint`, `float`, `double`, or `decimal` — for
example `(long)0`.

## Rule description

Casting a literal to a numeric type says the same thing as suffixing the literal itself (`(long)0` and `0L`
are equivalent), but the suffix form doesn't need the parentheses and reads as part of the literal rather
than as a conversion.

Only a literal that qualifies for [NE0012](ne0012.md)'s suffix outright is rewritten: no suffix already
present, and no decimal point or exponent. A literal with a fractional part is left alone, since rewriting it
would change its value once the cast's rounding is gone — for example `(long)1.5` truncates to `1`, but
`1.5L` isn't valid syntax and `1L` would silently change the meaning. A hexadecimal or binary integer literal
cast to `float`, `double`, or `decimal` is also left alone, since that format has no such suffix to add.

Generated code is skipped.

## How to fix violations

Replace the cast with the literal's suffix:

```csharp
// Before
long a = (long)0;
float b = (float)1;

// After
long a = 0L;
float b = 1F;
```

The code fix performs this rewrite for a single occurrence, and via Fix All for every occurrence in the
selected scope.

## Suppress a warning

```csharp
#pragma warning disable NE0013
#pragma warning restore NE0013
```
