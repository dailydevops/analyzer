# NE0004: Use the 'is null' pattern instead of '== null'

| Property   | Value      |
|------------|------------|
| Rule ID    | NE0004     |
| Category   | Usage      |
| Severity   | Warning    |
| Code fix   | Yes        |

## Cause

A value is compared against `null` with the equality operator — `x == null` or `null == x` — where the
built-in reference/`Nullable<T>` equality applies.

## Rule description

A `==` comparison can be redefined by a user-defined `operator ==`, so `x == null` does not always mean "is
this null". The `is null` constant pattern always performs a reference null check and cannot be overridden, so
it states the intent unambiguously.

The diagnostic is reported regardless of the project's C# language version; the code fix is offered only when
the language version can compile the pattern (see below).

- Only the built-in equality is flagged. A comparison bound to a user-defined `operator ==` is left alone,
  because the pattern would change its semantics.
- The non-null operand must be able to take the pattern: a non-pointer reference type, a `Nullable<T>`, or an
  unconstrained type parameter. Pointers and non-nullable value types are skipped.
- Comparisons inside a LINQ expression tree (`Expression<T>`) are skipped, because the `is` pattern does not
  compile there.

## How to fix violations

Replace the comparison with the `is null` pattern:

```csharp
// Before
if (value == null) { }

// After
if (value is null) { }
```

The code fix performs this rewrite and preserves the surrounding trivia. Because the `is null` constant
pattern requires **C# 7.0**, the fix is registered only when the project's effective `LangVersion` is 7.0 or
later; on an older version the diagnostic still reports but no fix is offered.

## Suppress a warning

```csharp
#pragma warning disable NE0004
#pragma warning restore NE0004
```
