# NE0008: Use `<see cref="..."/>` instead of `<c>...</c>` or `<code>...</code>` for native/common type names

| Property   | Value         |
|------------|---------------|
| Rule ID    | NE0008        |
| Category   | Documentation |
| Severity   | Warning       |
| Code fix   | Yes           |

## Cause

An XML doc comment `<c>` or `<code>` element's entire content is a single recognized native/predefined C#
type name or common BCL value type name — for example `<c>string</c>`, `<c>int</c>`, `<code>bool</code>`,
or `<c>Guid</c>`.

## Rule description

`<c>` and `<code>` mark text as inline or block code with no further meaning attached. `<see cref="..."/>` is
the dedicated construct for referencing a type; IntelliSense and documentation generators render it as a
navigable link, and tools can validate that the referenced type actually exists.

The whole documentation-comment tree of a member is inspected — not only `<summary>`, but also `<param>`,
`<returns>`, `<value>`, `<exception>`, `<remarks>`, and `<typeparam>`, since the same `<c>type</c>` /
`<code>type</code>` mistake is equally possible in any of them.

Only the following native/predefined type names are recognized: `bool`, `byte`, `char`, `decimal`, `double`,
`float`, `int`, `long`, `object`, `sbyte`, `short`, `string`, `uint`, `ulong`, `ushort`, `dynamic`, `nint`,
`nuint`. `void` is intentionally excluded — it denotes the absence of a return type rather than an actual
type, and is instead covered by [NE0007](ne0007.md) alongside the other language keywords.

The following common BCL value type names are recognized as well, since the same `<c>type</c>` mistake is
just as common for them: `Guid`, `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly`, `TimeSpan`.

- A `<c>` or `<code>` element must contain *only* the type name, and nothing else. Code snippets, expressions,
  or any surrounding prose (`<c>x is string</c>`, `<c>the string value</c>`, `<c>List<int></c>`) are left
  alone.
- Generated code is skipped.

## How to fix violations

Replace the `<c>` or `<code>` element with `<see cref="..."/>`:

```csharp
// Before
/// <summary>Returns the result as a <c>string</c>.</summary>

// After
/// <summary>Returns the result as a <see cref="string"/>.</summary>
```

The code fix performs this rewrite for a single occurrence, and via Fix All for every occurrence in the
selected scope.

## Suppress a warning

```csharp
#pragma warning disable NE0008
#pragma warning restore NE0008
```
