# NE0007: Use `<see langword="..."/>` instead of `<c>...</c>` or `<code>...</code>` for C# keywords

| Property   | Value         |
|------------|---------------|
| Rule ID    | NE0007        |
| Category   | Documentation |
| Severity   | Warning       |
| Code fix   | Yes           |

## Cause

An XML doc comment `<c>` or `<code>` element's entire content is a single recognized C# keyword — for
example `<c>true</c>`, `<c>null</c>`, or `<code>default</code>`.

## Rule description

`<c>` and `<code>` mark text as inline or block code with no further meaning attached. `<see langword="..."/>`
is the dedicated construct for referencing a C# language keyword; IntelliSense and documentation generators
render it distinctly from generic code, and tools can validate that the referenced word is actually a
keyword.

The whole documentation-comment tree of a member is inspected — not only `<summary>`, but also `<param>`,
`<returns>`, `<value>`, `<exception>`, `<remarks>`, and `<typeparam>`, since the same `<c>keyword</c>` /
`<code>keyword</code>` mistake is equally possible in any of them.

Only the following unambiguous keywords are recognized: `true`, `false`, `null`, `default`, `this`, `base`,
`static`, `abstract`, `virtual`, `sealed`, `override`, `readonly`, `async`, `await`. Contextual keywords that
double as ordinary identifiers or prose words (`value`, `var`, `partial`, `nameof`, …) are intentionally
excluded to avoid flagging text that merely happens to match.

- A `<c>` or `<code>` element must contain *only* the keyword, and nothing else. Code snippets, expressions,
  or any surrounding prose (`<c>x == null</c>`, `<c>the true value</c>`, `<c>List<int></c>`) are left alone.
- Generated code is skipped.

## How to fix violations

Replace the `<c>` or `<code>` element with `<see langword="..."/>`:

```csharp
// Before
/// <summary>Returns <c>true</c> if the operation succeeded; otherwise, <c>false</c>.</summary>

// After
/// <summary>Returns <see langword="true"/> if the operation succeeded; otherwise, <see langword="false"/>.</summary>
```

The code fix performs this rewrite for a single occurrence, and via Fix All for every occurrence in the
selected scope.

## Suppress a warning

```csharp
#pragma warning disable NE0007
#pragma warning restore NE0007
```

## Interaction with Meziantou.Analyzer's MA0154

If [Meziantou.Analyzer](https://github.com/meziantou/Meziantou.Analyzer) is also active, its `MA0154`
("Use langword in XML comment") targets the same mistake. A `DiagnosticSuppressor` bundled with this package
suppresses `MA0154` wherever NE0007 already reports it, so both analyzers don't flag the same occurrence
twice. `MA0154` still fires on its own for anything NE0007 intentionally leaves alone (for example, a native
type name in a `<c>` element).
