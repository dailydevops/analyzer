# NE0009: Check for cancellation at the start of the method body

| Property   | Value   |
|------------|---------|
| Rule ID    | NE0009  |
| Category   | Usage   |
| Severity   | Warning |
| Code fix   | Yes     |

## Cause

A method with a block body accepts a `System.Threading.CancellationToken` parameter but does not check for
cancellation as the first statement of its body.

## Rule description

A method that accepts a `CancellationToken` should honor it as early as possible, before doing any other
work. The check must appear as the first statement of the method body, immediately after any leading
argument-validation guard clauses. Either of the following satisfies the rule:

```csharp
cancellationToken.ThrowIfCancellationRequested();
```

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return;
}
```

Leading argument-validation guard clauses are skipped over when locating "the start" of the body:

- An `if` statement whose sole statement throws an exception that is or derives from `System.ArgumentException`
  (covers `ArgumentException`, `ArgumentNullException`, `ArgumentOutOfRangeException`, and custom subclasses),
  for example `if (value is null) throw new ArgumentNullException(nameof(value));`.
- A call to a static `ThrowIfXxx` guard-helper method on a type whose name ends with `Exception`, for example
  `ArgumentNullException.ThrowIfNull(value)` or `ArgumentException.ThrowIfNullOrEmpty(text)`.

The very next statement after the last guard clause (or the very first statement, if there are no guard
clauses) must be the cancellation check. If a method declares more than one `CancellationToken` parameter,
checking against any one of them satisfies the rule.

- Expression-bodied methods (`=>`) are skipped, since they cannot structurally hold a guard statement or a
  cancellation check.
- Methods without a body — interface member declarations, `abstract` methods, `extern` methods, and `partial`
  method declarations without an implementation — are skipped, since there is no body to check.
- Only ordinary method declarations are inspected; local functions are not.
- Generated code is skipped.

## How to fix violations

Add a cancellation check as the first statement after any leading guard clauses:

```csharp
// Before
public async Task ProcessAsync(Item item, CancellationToken cancellationToken)
{
    ArgumentNullException.ThrowIfNull(item);

    await SaveAsync(item).ConfigureAwait(false);
}

// After
public async Task ProcessAsync(Item item, CancellationToken cancellationToken)
{
    ArgumentNullException.ThrowIfNull(item);

    cancellationToken.ThrowIfCancellationRequested();

    await SaveAsync(item).ConfigureAwait(false);
}
```

The code fix offers two independent forms — inserting `token.ThrowIfCancellationRequested();`, or inserting
`if (token.IsCancellationRequested) { return ...; }` — for a single occurrence, and via Fix All for every
occurrence in the selected scope. The statement inside the `if` is chosen to match the method:

- `yield break;`, inside an iterator method (one that already uses `yield return`/`yield break`) — `return
  value;` does not compile there at all, regardless of return type.
- A bare `return;`, for a `void`-returning method, or an `async` method returning (non-generic) `Task` or
  `ValueTask`.
- `return [];`, when the effective return type — `T` for an `async` method returning `Task<T>`/`ValueTask<T>`,
  or the declared return type otherwise — is one of the well-known collection shapes (an array, or a generic
  `List<T>`/`ISet<T>`/`ImmutableArray<T>`/`Span<T>`/etc. — see the code fix for the exact set) *and* the
  project's language version supports collection expressions (C# 12+).
- `return default;` otherwise — always syntactically legal, even where it is only a semantic placeholder (for
  example a non-`async` method returning `Task<T>`, where the statement's target type is `Task<T>` itself, not
  `T`, so `Task.FromResult(...)` — not attempted by this mechanical fix — would be needed for a meaningful
  value).

## Suppress a warning

```csharp
#pragma warning disable NE0009
#pragma warning restore NE0009
```
